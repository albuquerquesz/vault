# PRD: Login UI Rebuild (Image-Based)

## 1. Objective
Rebuild `apps/web/src/routes/login.tsx` to match the provided visual reference: a split-screen, dark, premium login experience with strong typography and minimal, high-contrast controls.

## 2. Scope
- In scope: Frontend/UI only for the login screen.
- Out of scope: Authentication logic changes, backend/API, OAuth flow behavior.

## 3. Target Layout
- Full-height viewport split into two columns on desktop.
- Left panel (~33% width): brand message area.
- Right panel (~67% width): centered login form area.
- Mobile/tablet behavior:
  - Collapse to single-column.
  - Preserve hierarchy (brand intro above or hidden based on breakpoint strategy).
  - Keep all form actions accessible without horizontal scroll.

## 4. Visual Direction
- Theme: near-black background with subtle radial/vertical lighting and faint grid texture.
- Borders: soft, low-contrast separators (not heavy outlines).
- Typography:
  - Bold headline in left panel.
  - Clean, compact form typography on right panel.
  - Maintain strong contrast and readable secondary text.
- Spacing: generous negative space, centered form block.

## 5. UI Components

### 5.1 Left Panel
- Top-left back navigation text link (e.g., "Home").
- Main headline + supporting paragraph.
- Bottom-left testimonial quote.

### 5.2 Right Panel
- Brand/logo at top center.
- Main title: "Sign In or Join Now!"
- Subtitle text below title.
- Social auth buttons (stacked):
  - Continue with Google
  - Continue with Vercel
  - Continue with GitHub
- Divider with "OR".
- Email input with leading icon.
- Primary submit button: "Continue With Email".

## 6. Interaction & States
- Hover/focus states for all buttons/inputs aligned with dark theme.
- Keyboard focus visibility must be clear.
- Input validation/error slot should be visually reserved (even if logic is unchanged).
- Keep loading/disabled visual states consistent with existing design system.

## 7. Accessibility Requirements
- Proper label/aria for input and action buttons.
- Logical tab order.
- Contrast compliant for text and controls.
- Semantic structure (`main`, headings, form landmarks).

## 8. Technical Constraints
- Implement only in `apps/web/src/routes/login.tsx` and directly related presentational components if needed.
- Reuse existing UI primitives and tokens when available.
- Do not change auth provider behavior or request payloads.

## 9. Acceptance Criteria
- The login page visually matches the reference image in structure, spacing, and tone.
- Desktop split layout and mobile responsive behavior are implemented.
- Social buttons, email field, and CTA are present in correct order.
- UI passes basic accessibility checks (focus, labels, contrast).
- No regressions in existing login functionality.
