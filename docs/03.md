# PRD: Global Light Mode Rollout (Excluding Login)

## 1. Objective
Enable a production-ready Light Mode across all authenticated and public app screens, while keeping the login screen (`/login`) locked to its current dark visual design.

## 2. Scope
- In scope:
  - Light Mode support for all routes/components except login.
  - Theme toggle behavior, token usage, and visual QA.
  - Persisted user preference and predictable default theme.
- Out of scope:
  - Rebuilding login UI.
  - Backend/API changes.

## 3. Functional Requirements

### 3.1 Theme Availability
- App must support both `dark` and `light` themes.
- Users can switch theme from existing UI control (or add one if missing).
- Theme preference must persist across refresh/session.

### 3.2 Route Exception (Login)
- `apps/web/src/routes/login.tsx` must always render in dark mode styling.
- Theme toggle/global theme state must not visually override login palette.

### 3.3 Token-Driven Styling
- All screens (except login) must rely on design tokens (`background`, `foreground`, `border`, `muted`, etc.) instead of hardcoded dark colors.
- Replace hardcoded dark-only classes that break legibility in Light Mode.

## 4. UX & Visual Requirements
- Light Mode must maintain hierarchy, contrast, and spacing parity with current dark mode.
- Charts/cards/tables/forms/sidebar/header must remain readable and consistent.
- Hover/focus/active/disabled states must be clear in both themes.

## 5. Accessibility Requirements
- Minimum contrast compliance for text and interactive elements in Light Mode.
- Visible keyboard focus states in both themes.
- No theme-induced content loss (icons, borders, placeholders, muted text).

## 6. Technical Constraints
- Prioritize existing theme system/provider and shadcn token conventions.
- Avoid per-component ad-hoc overrides unless strictly necessary.
- Keep implementation frontend-only.

## 7. Acceptance Criteria
- All routes except `/login` render correctly in Light Mode and Dark Mode.
- Login route remains visually dark regardless of selected app theme.
- No critical readability/contrast regressions in dashboards, forms, sidebar, and charts.
- Theme preference persists and applies consistently after reload.
